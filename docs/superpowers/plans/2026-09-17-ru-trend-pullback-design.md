# 橡胶 ru 日线趋势回踩策略 v1.0 — 设计文档

- 日期：2026-09-17
- 平台：聚宽（JoinQuant）回测验证；第二阶段移植迅投 QMT 实盘（本次不做）

## 1. 目标与范围

**目标**：单品种（天然橡胶 RU）日线趋势跟踪策略，在聚宽做回测验证逻辑正确性。

**范围边界**：

- 本次只做单品种 ru，后续再扩展固定品种池（本次设计中参数与结构应便于扩展）
- 本次只做聚宽回测，不做 QMT 实盘、不做实盘对接
- 不做：附加组合风控（最大回撤暂停/连亏暂停）、固定止盈、反手开仓、多周期组合

**验证通过判据（逻辑验证优先）**：

1. 回测跑通全区间无异常，无状态不一致告警
2. 交易明细逐笔抽查符合设计逻辑（主力合约正确、加仓 ≤2 次、止损线数值与公式吻合）
3. 成本（手续费+滑点）×2 后仍为正收益
4. 记录绩效指标（年化、最大回撤、胜率、盈亏比、手续费占比，"出场→重进"的次数与间隔分布，以及分多空拆解——多头/空头各自的收益、胜率、盈亏比、交易次数）供下一步调参
5. 单笔风险抽查：逐笔核算 `(入场价 − 止损线) × 手数 × 乘数 ÷ 当时权益` ≈ R=2%（因最低 1 手与取整，实际通常略低），验证仓位公式实现无误；确认同方向同时最多 3 笔、最坏一轮止损亏损 ≈ 3 笔之和（≈6%）

## 2. 策略规格

### 2.1 行情与执行时点

- 信号周期：日线；每个交易日 **14:45** 判定并执行
- 止损检查：**每分钟**（含夜盘 21:00–23:00），盘中实时触发
- 有夜盘品种一个交易日从前夜 21:00 开始，前夜 bar 归属次一交易日

### 2.2 趋势方向定义（多头）

- `MA20(D) > MA20(D-3)`（当日 MA20 较 3 个交易日前上行，跨度参数化 `ma_slope_days` = 3）

空头完全镜像：`MA20(D) < MA20(D-3)`。

方向由 MA20 自身状态定义——它是系统核心线（入场买它的支撑、出场卖它的失守）。短期均线（MA5/MA10）不参与方向判断：它们的生命周期与"价格在 MA20 下方停留数日再站回"的回踩形态天然冲突（回踩数日后 MA5 必被拖到 MA20 下方，且站回日前一天恰是仍在下方的最后一天）。

### 2.3 入场（多头，D 日 14:45 判定）

1. 趋势方向成立（见 2.2）
2. 回踩窗口：最近 N 个交易日（含 D）中存在某日 s 满足 `low(s) ≤ MA20(s)`，其中 `low(s)` 为该日高低点（含夜盘），`MA20(s)` 为该日的 MA20 值
3. 站回：`P1445(D) ≥ MA20(D)`
4. 距离上限：`P1445(D) − MA20(D) ≤ d_max × ATR20(D)`，防止站回日已涨离支撑太远（d_max=0 表示不限）
5. 深失守过滤：回踩窗口内任一日 s 满足 `MA20(s) − low(s) > p_break_max × ATR20(D)`（统一用信号日 ATR 作尺度）则窗口作废，`p_break_max=0` 表示不限（现状）

N 默认 3。`P1445(D)` 为 14:45 分钟 bar 收盘价，`low(D)` 为 D 交易日全时段（前夜 21:00 起至 14:45）最低价。**N=1 且 d_max=0 时精确还原同根 K 线规则**（`low(D) ≤ MA20(D)` 且 `P1445(D) ≥ MA20(D)`）。

空头镜像：最近 N 日内存在 s 满足 `high(s) ≥ MA20(s)`；今日 `P1445(D) ≤ MA20(D)` 且 `MA20(D) − P1445(D) ≤ d_max × ATR20(D)`；深失守镜像：任一日 s 满足 `high(s) − MA20(s) > p_break_max × ATR20(D)` 则窗口作废。

### 2.4 出场（三类，全部按"每笔仓位"或"全部仓位"区分）

| 机制 | 多头条件 | 执行范围 |
|---|---|---|
| 信号反转 | `P1445(D) < MA20(D) − signal_exit_dist_atr×ATR20(D)` | 全部平仓 |
| 初始止损 | 分钟 bar 低点 ≤ `入场价 − stop_loss_dist_atr×ATR_lock` | 仅平该笔 |
| 移动止损 | 止损线 = `max(旧止损线, 持仓极值 − stop_loss_dist_atr×ATR_lock)`，只上移；分钟 bar 低点 ≤ 止损线 | 仅平该笔 |

- `ATR_lock` = 入场日 14:45 计算的 ATR20(D)，入场时锁定、不再变化
- 移动止损的"持仓极值"= 该笔入场以来所有分钟 bar 的最高价（多头），每分钟实时更新；锚点固定取**最高价**而非最高收盘价（理由见 §7 决策记录）
- 止损触发后按市价平仓（不挂限价）
- 空头镜像：信号反转 `P1445(D) > MA20(D) + signal_exit_dist_atr×ATR20(D)`；止损 `入场价 + stop_loss_dist_atr×ATR_lock`；移动止损只下移

**停板成交处理**：平仓单提交后校验是否成交（对比持仓数量或订单成交状态）；未成交（涨停/跌停封板，回测中 order 不成交）时打印警告日志（按 leg 记录状态，仅状态变化时打印，避免每分钟刷屏），不重复下单（该合约已有未成交委托则等待）；开板后按分钟 bar 止损逻辑继续处理，日终未成交委托由平台自动撤销，次日逻辑自然重试。

**已知特性（用户已知情）**：入场价 ≈ MA20，初始止损在 stop_loss_dist_atr×ATR 之外（默认 2.0），因此信号反转平仓绝大多数时候先于 ATR 止损触发；ATR 初始/移动止损的实际角色是小概率灾难保护（急跌、跳空、大幅回吐）。移动止损同时承担动态止盈职能，策略不设固定止盈。

### 2.5 加仓（金字塔，多头）

1. 入场条件（2.3）再次成立（含回踩窗口、距离上限与深失守过滤，即多根 K 线口径）
2. 已有持仓
3. 价差确认：`P1445(D) − 最近一笔入场价 ≥ add_min_dist_atr × ATR20(D)`（0 = 任意正浮盈即现状；站回价 ≈ 当前 MA20、上笔入场价 ≈ 当时 MA20，该条件等价于要求 MA20 自上一笔以来已实质推进）
4. 加仓次数 < 2（即总仓位最多 3 笔）

加仓手数按同一风险公式（2.7）计算——按**当次入场时点**的权益与该笔锁定的 ATR 独立计算（等风险，非固定等手数；50 万资金下实际多为每笔 1 手）；新 leg 独立锁 ATR、独立止损。加仓计数在「空仓 → 持仓 → 全部平仓」一轮结束后重置。

空头镜像：条件 3 为 `最近一笔入场价 − P1445(D) ≥ add_min_dist_atr × ATR20(D)`。

### 2.6 重新入场与反手

信号反转平仓后**不反手**，空仓等待新的、方向对称的独立入场信号。

**冷却期**：持仓全部平掉后（无论信号反转还是最后一笔止损触发），接下来 `cooldown_days` 个交易日内禁止开新仓。参数化，默认 0（关闭），回测扫 {0, 2, 3}。动机：回踩窗口 N=3 会把出场日前后都算作触及日，可能造成"出场 → 1~3 日内快速重进"的 churn；但快速重进也覆盖"假破位后重新上车"的合理行为，是否启用及取值由回测数据决定。

### 2.7 仓位公式

```
lots = max(1, floor(equity × R / (stop_loss_dist_atr × ATR_lock × 合约乘数)))
```

- `equity = context.portfolio.total_value`，`R = 2%`，合约乘数来自 `g.params` 的品种乘数字典（RU = 10；聚宽文档无乘数 getter，实现时实测 `get_security_info()`/Position 是否暴露 multiplier，不可用则维持字典）
- **最低 1 手**：极端高波动时允许单笔风险超过 2%
- 保证金约束：可用资金不足以开 `lots` 手保证金时，逐手减仓；1 手都开不出则跳过本次开仓并写警告日志

### 2.8 移仓（主力切换）

- 每日 14:45 检查 `get_dominant_future('RU')`；新合约需**连续 2 个交易日**被返回才确认为新主力（防抖），最多滞后 1 日移仓
- 确认切换且有持仓：**先开新、后平旧**——先在新主力合约等量开仓，成交后再平掉旧合约全部 legs；加仓计数保留
- 未成交处理：任一腿未成交（停板）→ 告警 + 后续 bar 重试该腿，不重复下单；**两腿全部成交后才更新 `g.legs`、`g.current_contract` 并做价差平移**
- 止损处理——**价差平移**：记 δ = 新合约成交价 − 旧合约成交价，`stop_line += δ`、`extreme += δ`，保留已锁定的移动止损进度；`entry_price` 更新为新合约成交价，`ATR_lock` 更新为新合约当日 ATR20（仅影响之后的移动止损推进）
- 无持仓时仅更新 `g.current_contract`，不产生交易
- 14:45 执行顺序：**信号反转出场 → 移仓 → 加仓 → 开仓**（当天要全平的日子不再白付一次移仓成本）

## 3. 数据与信号计算

- 信号、入场价、止损全部基于**当前实际主力合约**（如 `RU2601.XSGE`），不使用 9999 连续合约，保证信号价格与成交价格同源
- 日线序列：`attribute_history(contract, 30, '1d', ['high','low','close'])` 取 30 根，用于 MA20 与 ATR20
- **准当日日线**：用当日分钟 bar 合成 D 日 OHLC，收盘价用 14:45 bar 收盘价；high/low 为交易时段（含前夜）极值
- `MA20(D)`、`ATR20(D)` 用"前 29 根完整日线 + 准当日日线"合成序列计算，避免未来数据；回踩窗口内历史日 s 的 `MA20(s)` 直接取同一日线序列上的滚动均线值
- ATR20 = 最近 20 个交易日 TR 均值；`TR = max(H−L, |H−C_prev|, |L−C_prev|)`
- MA/ATR 用 pandas/numpy 直接计算（与现有 joinquant 策略一致，不引入 talib）

### 参数总表（集中 `g.params`）

## 4. 代码结构与执行流程

单文件、函数式，风格对齐 `joinquant/03-守正出奇4.0.py`：中文注释、英文日志（FIX-10 实践）、参数集中 `g.*`、`initialize` 用 try/except 包裹。

### initialize 设置

```python
set_subportfolios([SubPortfolioConfig(cash=init_cash, type='futures')])
set_option('use_real_price', True)
set_option('avoid_future_data', True)
set_option('futures_margin_rate', 0.12)
set_order_cost(OrderCost(open_commission=0.000023, close_commission=0.000023,
                         close_today_commission=0.000023, open_tax=0, close_tax=0,
                         min_commission=0), type='futures', ref='RU')
set_slippage(PriceRelatedSlippage(0.0003), type='futures')   # type 取值待平台实测
set_benchmark('RU9999.XSGE')                                  # 不支持则退回默认
log.set_level('order', 'error')
log.info('PARAMS: %s' % sorted(g.params.items()))             # 参数快照（扫参对比用）
run_daily(risk_and_signal_routine, time='every_bar')          # 回测频率必须选"分钟"
```

### 分钟 bar 流程（单入口，避免多定时任务时序竞争）

```
risk_and_signal_routine(context):
  1. 一致性校验：g.legs 与 context.portfolio 实际持仓比对，不一致→以实际为准+告警修正
  2. 移动止损更新 + 止损触发检查（每笔独立，触发即市价平该笔；提交后校验成交，停板未成交→告警+等待，不重复下单）
  3. 若当前时间 != 14:45: return
  4. 若 g.last_signal_date == 今日: return   # 幂等
  5. 信号反转出场（失守 → 全部平仓）
  6. 移仓检查（确认主力切换 → 先开新后平旧 → 价差平移；空仓则仅更新记录）
  7. 加仓判断
  8. 开仓判断（空仓且冷却期已过）
  9. g.last_signal_date = 今日
```

### 状态

- `g.legs`：list，每条 `{contract, side, lots, entry_price, entry_date, atr_lock, extreme, stop_line}`
- `g.current_contract`：当前记录的合约；`g.dominant_counter`：新主力连续确认计数（防抖用）
- `g.last_signal_date`：幂等标记，取自然日即可（14:45 处于日盘时段，无夜盘归属歧义）
- `g.last_flat_date`：最近一次全平日期（冷却期计算用）
- `context.portfolio` 为实际持仓的最终事实来源，`g.legs` 与之每 bar 校验

## 5. 回测配置与成本

- 区间：2018-01-01 至今；初始资金：50 万；频率：分钟
- 手续费/滑点见 initialize 设置，参数化，回测做 ×2 / ×3 敏感性
- 日志逐条打印：开仓/加仓/止损/移仓/信号出场（合约、价格、手数、ATR_lock、止损线、触发原因）

### 参数纪律与敏感性粗扫（防过拟合）

- 参数只允许逻辑驱动的调整（k 源于三线重合、cooldown 源于防 churn），**禁止绩效驱动的网格寻优**——单品种约 8 年日线样本太薄，网格搜索必然拟合噪声且无法证伪
- 敏感性粗扫：每个参数在默认值附近取 3 个值、逐个重跑，绩效形态平稳（不出现"盈利翻亏"断崖）即通过；目的是验证稳健性，不是找最优值
- 起始扫 `signal_exit_dist_atr` {0, 0.5, 1.0}、`cooldown_days` {0, 2, 3}、`pullback_max_break_atr` {0, 1, 1.5, 2}、`add_min_dist_atr` {0, 0.5, 1.0}（参数表已标注）；其余参数仅在绩效形态脆弱时追加
- 样本外（可选）：最后 2 年 holdout，参数定稿后只验证一次
- 据目前了解聚宽无批量回测接口，扫参为手动改参重跑；每次回测日志首行打印参数快照（§4），便于跨次对比

## 6. 实现时需在聚宽实测验证的假设

文档依据为聚宽 API 文档（2017 版）与既有策略实践，以下行为需在平台实测确认，实现时逐项验证：

1. `attribute_history(unit='1d')` 在盘中是否已含当日未完成 bar（含：替换最后一根；不含：追加）
2. `set_slippage` 是否支持 `type='futures'`，不支持则用全局设置
3. `set_benchmark('RU9999.XSGE')` 是否被接受
4. `get_dominant_future('RU')` 在回测历史日期逐日调用
5. 期货 `order()` 的 `side='long'/'short'` 与平今仓手续费实际行为
6. 分钟数据取数上限、夜盘 bar 的交易日归属过滤
7. `get_security_info()` / Position 对象是否暴露合约乘数（不可用则用品种乘数字典）
8. 保证金不足时下单的失败/截断行为（决定最低 1 手时的保护逻辑）
9. 停板时订单状态细节：未成交市价单是否列于 `get_open_orders()`、日终撤销后的订单状态——用于实现"不重复下单"判定（已知：涨停/跌停时 order 不成交）

## 7. 关键设计决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 信号基准合约 | 实际主力合约，非 RU9999 | 信号价与成交价同源；与 QMT 实盘行为一致；已知代价：换月前后 MA20/ATR20 因新旧合约基差有台阶跳变，v1 接受，v2 再评估 δ 校正 |
| 移仓 | 显式移仓 + 2 日确认防抖 + 止损价差平移 + 先开新后平旧 | 不依赖平台黑盒（QMT 实盘必须显式做）；防抖避免临界期往返成本；平移保留已锁定的移动止损进度；先开新后平旧：主要失败场景"新合约买不进"不改变状态、次日天然重试，保证金短时双占在 50 万下可忽略 |
| 出场主导 | MA20 缓冲线主导，ATR 止损为灾难保护 | 入场价贴近 MA20，止损远在 stop_loss_dist_atr×ATR 外（默认 2.0） |
| 风险预算 | R=2% + 最低 1 手 | 50 万资金下 R=1% 会在大波动期开不出仓，与趋势跟踪意图相反 |
| 架构 | `run_daily(every_bar)` 单入口 | 与 02-v6.6 的 minute_level_stop_loss 惯例一致；单入口避免时序竞争 |
| 回踩形态 | 回踩窗口 N=3 + 距离上限 1.0×ATR | ru 常隔日才收回 MA20，同根 K 线约束会大量错过机会；N=1+不限距可还原原规则 |
| 方向定义 | 仅 MA20 上行（`MA20(D) > MA20(D-3)`） | 任何"MA5/MA10 当前在 MA20 上方"的条件都与"价格在 MA20 下方停留数日后站回"的回踩形态冲突（MA5 被拖低，且站回日前一天恰是下方最后一天）；方向改由核心线 MA20 自身状态定义，短期均线退出 |
| 固定止盈 | 不做 | 趋势策略收益集中在右尾，固定止盈截断右尾降低期望；移动止损已承担动态止盈职能；每笔常 1~2 手，分批难以执行 |
| 贴线 churn | 参数化冷却期（默认关，回测扫参） | 出场后 1~3 日快速重进既可能是磨损 churn、也可能是"假破位后重新上车"的合理行为，由回测数据决定是否启用 |
| 极端行情停板 | 平仓单未成交→告警+等待，不重复下单，开板后按分钟逻辑继续 | 停板时平仓单无解，追单无意义；平台日终自动撤销未成交委托，次日自然重试 |
| 深失守作废窗口 | 参数化 `pullback_max_break_atr`（默认 0 关，回测扫参） | 窗口内深跌超过阈值属"破位后反抽"而非回踩，信号质量差；过滤是否有效由回测数据决定 |
| 加仓价差 | 最小浮盈 `add_min_dist_atr`（默认 0.5，扫 {0, 0.5, 1.0}） | 纯"正浮盈"在 MA20 走平的震荡段会让 3 笔叠在几乎同一价位（伪金字塔），"上笔已证明正确"形同虚设而最坏风险仍是 3R；最小价差等价于要求 MA20 自上一笔以来已实质推进 |
| 移动止损锚点 | 取最高价，非最高收盘价 | 标准吊灯式做法；最高价与收盘价之差 ≈ 0.3~0.5 ATR，相对 stop_loss_dist_atr（默认 2.0）缓冲为二阶差异；"峰值日收盘"写法在新高日收盘差时会破坏单调性；若回测日志出现"插针后紧接被止损"的 whipsaw 案例，v2 再评估"最高收盘价" |
