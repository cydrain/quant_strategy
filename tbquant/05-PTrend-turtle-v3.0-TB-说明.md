## 2. 工作原理

- **单图层方案**：只挂 P9888（主力连续）1 分钟图。日线 N 值/四通道由公式内生聚合：
  按 `TradingDate()` 分组累计 1 分钟 bar 成"当日高/低/收"，交易日切换时入环（容量 61 根，
  对齐聚宽 `attribute_history(need+1)` 窗口），再用与聚宽 `calc_n` 完全一致的递归式算 N：
  前 20 个 TR 简单平均初始化，之后 `N=((NSmooth-1)*N+TR)/NSmooth`。
  夜盘 21:00 的 bar 的 TradingDate 已是下一交易日，因此聚合出的日 K 与期货交易所口径一致。
- **信号检查全部为分钟级**，顺序与聚宽一致，每根 bar 只执行一个动作：
  ① 共享止损（2N）→ ② 反向突破出场（前 ExitN 日反向极值）→ ③ 顺向加仓（每 0.5N）→ ④ 突破入场（前 EntryN 日极值）。
- **手数**：`权益 × UnitRisk ÷ (N × MultiplierP)` 向下取整、最低 1 手；再按可用资金、
  保证金占用上限（权益 × MarginCapPct）逐档限手，完全复刻聚宽 `unit_lots + fit_margin + fit_cap`。
- **台账自愈**：公式维护持仓台账（手数/unit 数/最近 unit 价/止损线）。每根 bar 与平台持仓比对，
  不一致（重启、部分成交、停板未成交）自动按平台持仓重建，等效聚宽 `check_state_consistency`。
- **移仓**：使用平台原生机制（后复权+真实价格+除权自动换仓+委托映射主力，等持仓量换仓），
  主力代码变化时（`MainSymbol()`）自动重建止损/加仓基准。
- **资金口径**：回测用 `Portfolio_CurrentEquity / Portfolio_CurrentCapital`；
  实盘/模拟（策略交易模式且账户在线）自动切换 `A_CurrentEquity / A_FreeMargin`。无需手改。

## 3. 快速上手（回测）

> **⚠️ 先调大图表"加载 K 线数量"**：TB 按"**从最新往回 N 根**"加载数据（N=图表该设置的值）。
> P9888 的 1 分钟全量从 2025-01-02 到最新约 **15.5 万根**，默认 5 万根只能回溯到 2026-03 前后 →
> 视口停在 2025-01 时图面全空（5 分钟全量仅约 2.9 万根，低于上限所以正常显示）。
> 跑探针前把 1 分钟图的加载数量调到 **≥16 万（建议 200000）**，待 1 分钟图能看到 2025-01 的数据后再回测。

1. **先跑探针**（约 1 分钟数据量，很快）：
   - 打开策略研究/公式编辑器，新建公式，粘贴 `PTrendTurtle_Probe.txt` 全文，命名如 `PTrendTurtle_Probe`，编译通过。
   - 挂 P9888 **1 分钟**图，回测区间 `2025-01-02 ~ 2025-01-10`，运行模式选 **K线收盘模型**。
   - 跑完在公式目录找 `PTrendTurtle_Probe_日志.txt`（关键行同时打印到日志窗口），按第 4 节核对。
2. **跑主公式**：
   - 新建公式，粘贴 `05-PTrend-turtle-v3.0-TB.txt` 全文，建议命名 `PTrendTurtle_v3`（公式名会用于日志文件名）。
   - 挂 P9888 **1 分钟**图；**回测起点 = 切片起始日往前约 4 个月**（预热建日线环）；
     通过参数 `TradeStartDate` 控制实际开仓日（起点与开仓日分离，预热期不交易）。
   - 回测设置：初始资金 100 万；保证金率/手续费/滑点在公式 OnInit 内已设置（12% / 0.000023 按金额 / 1 跳），
     回测对话框保持默认即可（公式设置优先）。频率 1 分钟。
3. **读结果**：打开回测报告 + 公式目录下 `PTrendTurtle_v3_日志.txt`，按第 8 节与聚宽记录对拍（切片 1/4/5/6 的实测对照已归档在第 7 节）。

## 4. 探针（PTrendTurtle_Probe）判读表

探针在回测 `2025-01-06` 当天做 7 笔受控下单（T1~T7），并记录边界时间标签、合约属性、资金函数有效性。

| 项 | 探针输出 | 结论/动作 |
|---|---|---|
| R1 撮合模型 | T3 `Buy(1, High()+50)` 若 CC 不变=不成交 → **严格见价模型**；若成交@Open → 优价模型 | 主公式两种模型都能正确成交（指令价都取 bar 内可实现价，跳空时改用开盘价） |
| R1 成交价 | T1 次 bar 的 `AvgEntry/LastEntry` 应 ≈ T1 bar 的 Open（严格模型） | 若成交价与下单价有固定偏移，即为滑点作用，调 `SlippageTicks` |
| R2 交易日 | 周五 21:00 的 bar `TradingDate` 应为**下周一** | 是 → 夜盘聚合逻辑成立；否 → 把 `night` 段发现告诉我再调整 |
| R3 数组持久 | `PB.size` 随 bar 递增（1000/5000/10000 采样） | 是 → Vars 数组跨 bar 持久成立 |
| R4 合约属性 | `ContractUnit=10, ContractSize=10, MinMove=2`（实测另有 `BigPointValue=1`，不影响） | 主公式不依赖平台函数：手数/保证金均用自持参数 `MultiplierP=10` 计算，实测已闭环（第 12 节） |
| R5 时间标签 | 14:43~14:47 采样中恰有一根 `H=14,M=45` | 保证每日一次定时日志；若标签为区间起点/终点差异不影响逻辑 |
| R6 资金函数 | 回测下 `Portfolio_*` 有值；`A_AccountDataExist` 在回测下为 False | 主公式自动走回测分支；若在回测下 A_* 也为 True，请告知（可能需要调整 IsLiveTrade 判定） |
| R7 成交即时性 | T1 同 bar `MP/CC` 已刷新 → 下单当 bar 即时成交 | 是 → 台账当 bar 记账成立 |
| 冒烟 | 全部 `设置: ... ok`；结束行 `Stage=15` | 探针自身运行完整 |

> 探针已实测（v2，2026-10-03），结果见第 12 节。

## 5. 参数说明（主公式 `Params`）

| 参数 | 默认 | 含义 | 聚宽对应 |
|---|---|---|---|
| FixedDir | 1 | 1=只做多 / -1=只做空 / 0=双向 | `fixed_dir` |
| NPeriod | 20 | N（ATR）周期 | `n_period` |
| NSmooth | 20 | N 平滑系数 | `n_smooth` |
| EntryN | 20 | 入场通道周期（系统1=20） | `entry_n` |
| ExitN | 10 | 出场通道周期（系统1=10） | `exit_n` |
| UnitRisk | 0.01 | 1 unit 风险预算（权益占比） | `unit_risk` |
| MarginCapPct | 0.10 | 保证金占用上限（权益占比，0=不限） | `margin_cap_pct` |
| MaxUnits | 4 | 最大 unit 数（含首仓） | `max_units` |
| AddStepN | 0.5 | 每 0.5N 顺向加 1 unit | `add_step_n` |
| StopDistN | 2.0 | 止损距离（N 倍数） | `stop_dist_n` |
| S1Skip | 0 | 1=系统1 跳过规则（上次突破盈利→跳过下一次同类突破） | `s1_skip` |
| TradeStartDate | 20200313 | 开始交易日期 yyyymmdd；之前只预热不交易 | 聚宽回测起点 |
| InitCapital | 1000000 | 初始资金（回测） | 100 万 |
| MultiplierP | 10 | 合约乘数（元/点/手，P=10 吨/手×1 元/吨） | `multiplier` |
| MarginRateP | 0.12 | 保证金率 | `futures_margin_rate` |
| CommissionRateP | 0.000023 | 手续费率（按成交金额） | `open_commission` 等 |
| SlippageTicks | 1 | 滑点（跳；P 一跳=2 元/吨）。聚宽 0.0003 相对价 ≈ 1.35 跳 | `PriceRelatedSlippage(0.0003)` |
| MapToMain | 0 | 订单映射主力：0=不映射（单合约图）；1=委托映射真实主力（主连图回测/实盘） | —（平台机制） |
| LogHour / LogMinute | 14 / 45 | 每日定时日志时刻 | `signal_time` |

## 8. 对拍方法

1. 回测跑完后打开日志 `PTrendTurtle_v3_日志.txt`，重点行：
   - `entry OPEN` / `add OPEN`：开仓与加仓（dir/lots/px/N/stop/units）
   - `stop CLOSE` / `exit_breakout CLOSE`：平仓（含 pnl）
   - `ROLLOVER` / `STATE_REBUILD`：移仓与台账重建
2. **锚点核对（切片 6，TB 实测）**：
   - `2025-02-07 13:30` 开多 **5 手 @ 8830**（聚宽 13:31 @8830）
   - `2025-02-10 09:00` 加 **4 手 @ 8928.3**（聚宽 09:01 @8948）
   - `2025-03-04 09:00` 平 **9 手 @ 8994**，盈亏 **+10,760**（聚宽 @8974，+8,240）
   - 段末权益 TB 1,010,400 / 聚宽 1,008,240（Δ+2,160，完整对照见第 7 节）
3. 逐切片与 `joinquant/05-PTrend-request.md` 下表对照（时间/方向/手数/价/盈亏），接受第 9 节的已知差异；切片 1/4/5/6 的已完成对照见第 7 节。
4. 判定标准建议：**方向、手数、时间（±1 分钟）必须一致**；价格允许 1~数跳差（滑点模型）；
   非换月段的平仓盈亏偏差 ≤ 2%；换月段允许更大偏差（机制不同，见第 9.3 条）。

## 9. 已知差异清单（与聚宽不可完全复现部分）

1. **成交时点/价模型**：TB 按指令价撮合（bar 内按指令价、越界按 bar 边界；探针实测见第 12 节 R1），聚宽市价单按
   当前 bar 收盘价 ± 滑点。逐笔价格可能差 1~数跳，手数与时间应基本一致。
2. **滑点**：聚宽 0.0003 相对价 ≈ 1.35 跳；TB 默认 1 跳。想更接近可把 `SlippageTicks` 试探性设为 1.35（若平台接受小数）。
3. **移仓机制**：聚宽 = "连续 2 个交易日确认 + 14:45 手动平旧开新平移"；
   TB = 原生除权自动换仓（按持仓量），换仓日与换仓价可能不同。
   受影响的主要是"被换月事件切开的持仓"及其盈亏归集，合计层面可能偏差（≈换月价差×手数），对拍时优先对齐非换月段。
4. **夜盘通道口径**：TB 聚合日 K 含夜盘段（交易所口径）；聚宽在夜盘时段用"当日日盘合成 K"，
   夜盘 21:00~23:00 内 N/通道可能有细微差异，可能造成夜盘边缘信号 ±1 根 bar。
5. **预热窗口**：TB 需从回测起点物理预热（≥4 个月 1 分钟数据）；聚宽 `attribute_history` 自动回溯。
   预热期不交易，不影响回测统计口径。
6. **±1 手**：保证金上限/可用资金四舍五入的边界处，两边可能差 1 手（已按同口径逐档限手，概率很低）。
7. **停板/无流动性**：TB 严格撮合可能拒绝成交（日志 `OPEN_FAIL/CLOSE_FAIL`），下一 bar 重试；
   聚宽假设市价必成。极端行情下 TB 可能晚 1~数分钟。
8. **单 bar 单动作**：两边都遵循"每 bar 只做一件事"，但 bar 内多事件并发（如同分钟内触及止损又满足加仓）
   的取舍顺序在边界行情下可能表现不同（TB 为：止损>出场>加仓>入场）。

## 10. 模拟交易 / 实盘部署

1. **图表**：P9888，1 分钟；图表"加载 K 线数量"调大到覆盖预热 4 个月（从最新往回约 3 万根，建议 **40000**；该设置同时决定图表能看到多早的数据）。
   公式启动后先回放历史 bar 建立日线环，环满后才有信号（日志 `ring=` 可查进度）。
2. **运行模式**：必须 **K线收盘模型**。逐笔模式会每个 tick 触发 OnBar，不适合本公式。
3. **账户**：在交易单元/图表挂接模拟或实盘期货账户。公式自动判别：
   策略交易模式且账户在线 → 资金用 `A_CurrentEquity/A_FreeMargin`（日志 `IsLiveTrade=True`），
   下单价格用盘口（开多用卖一、开空用买一、平仓用对手价）。
4. **主力映射**：`SetOrderMap2MainSymbol()` 委托自动映射真实主力合约；换仓由平台"除权自动换仓"完成（等持仓量）。
5. **断线/重启**：重挂公式 → 历史回放重建日线环 → 首个有效 bar 出现 `STATE_REBUILD` 日志，
   按账户实际持仓恢复台账与止损基准。注意：
   - `UnitCount`（unit 数）按平台建仓次数恢复，极端情况下与真实档位可能差 1；
   - `S1Skip` 跳过标记不跨重启保存；
   - 若重启后仍无 `STATE_REBUILD` 但有持仓，请检查日志并在群内反馈。
6. **风险提示**：海龟策略为趋势跟踪，切片为"已知行情"的参数验证；实盘前建议先模拟盘跑 ≥1 个月，
   核对日志与实际委托的一致性后再上实盘。

## 11. 日志关键行速查

| 关键字 | 含义 |
|---|---|
| `entry OPEN` / `add OPEN` | 开仓/加仓成功（附 dir/lots/px/N/stop/units） |
| `OPEN_SKIP` | 手数不足跳过（保证金或上限约束） |
| `OPEN_FAIL` / `CLOSE_FAIL` | 委托被拒（停板等），下一 bar 自动重试 |
| `stop CLOSE` | 2N 共享止损平仓 |
| `exit_breakout CLOSE` | 反向突破出场 |
| `S1_SKIP` / `BREAKOUT_SKIP` | 系统1 跳过规则触发 |
| `ROLLOVER` | 主力合约切换（原生自动换仓），随后可能伴随 `STATE_REBUILD` |
| `STATE_REBUILD` | 台账按平台持仓重建（重启/不一致自愈） |
| `LEDGER_CLEAN` | 空仓残留台账清理 |
| `DAILY` | 每日 14:45 定时快照（N/四通道/units/stop/equity/ring） |
| `=== 运行结束` | 最后一根 bar 汇总 |
