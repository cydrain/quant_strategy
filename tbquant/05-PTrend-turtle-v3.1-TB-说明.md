# 05-PTrend-turtle-v3.1 TBQuant 公式版 使用说明

> 适用文件：`tbquant/05-PTrend-turtle-v3.1-TB.txt`（公式名 PTrendTurtle_v31，TBQuant 2.x；原 v4.0-TB，2026-10 更名）
> 移植基准：`joinquant/05-PTrend-turtle-v3.1.py`（聚宽 · 棕榈油 P 海龟策略）
> 前版对照：`tbquant/05-PTrend-turtle-v3.0-TB.txt`（单图层 · 1 分钟自聚合日线环）
>
> **v3.1 与 v3.0 的差别**：交易逻辑（N/四通道/手数/止损/加仓/出场/台账自愈/移仓）完全不变；
> 数据来源从「1 分钟 bar 现场聚合日线环」改为「**双图层直读日线数据源**」。
> 因此：**重跑无需关闭图表重开**（v3.0 的环数组限制不适用），且预热要求转移到日线图层的历史深度上。

## 3. 挂载与通用前置条件（三模式通用，缺一不可）

1. **双图层挂载（v3.1 硬性要求）**：
   - `data0` = 目标合约 **1 分钟**（单合约如 P2505，或主连 P9888）——全部信号/风控/下单在此层执行；
   - `data1` = **同合约日线（1d）**——纯只读数据源，仅提供 N/四通道数据。
     （实验用法：也可挂 30 分钟等日内周期 data1——N/四通道随每根完整K收完推进，即真 30 分钟海龟；
     该口径的 Data1[0]/[1] 盘中对齐尚未经探针复验，上实盘前先验证。）
   - N/四通道刷新节奏：**每根新 K bar 生成时在 `OnBarOpen` 刷新一次**（不随 tick 重复）——
     取值随 data1 窗口头推进更新：日线约每日一次、30 分钟约每 30 分钟一次。
   - 追加方法：策略研究中选中策略单元 → 右键数据源 → 周期选 **1d** → 追加。
   - 两图层都右键「**同步为主商品数据范围**」，避免回测起止错位。
2. **运行模式必须选「K线收盘模型」**（逐笔模型每 tick 触发 OnBar，不适合本公式）。
3. **参数 `MapToMain`**（唯一需要按场景切换的参数）：
   - `False`（默认）：单合约切片图（如 P2505）——数据不复权、不映射，订单留在图合约。
   - `True`：主连图（P9888）/ 实盘口径——开启后复权、映射真实价、自动换仓、委托映射主力。
   - ⚠️ 单合约图勿开 True：订单会被路由到主力合约。
4. **日线历史深度（最关键，切片 5 事故点）**：日线源在**首个目标信号日之前必须已有 ≥61 根日线**
   （WinSize=61 ≈ 3 个月交易日）。历史不足时读数可能仍是"有效值"而非无效值 → N 静默偏高、
   甚至窗口退化产生假突破。**修复 = 把图表数据范围（两图层同步）提前到首个目标信号日前 ≥61 个交易日。**
5. **数据源自检**：OnInit 日志会打印 `data0`/`data1` 的合约与周期（如 `data0.Symbol=p2405.DCE(1m)`、
   `data1.Symbol=p2405.DCE(1d)`）并做一致性检查；缺层/错位时不仅记 ERROR，运行期还会归 0 拒绝交易——
   每次运行前扫一眼日志头部。

## 4. 回测怎么用

### 4.1 步骤

1. 新建公式：粘贴 `05-PTrend-turtle-v3.1-TB.txt` 全文，建议命名 **PTrendTurtle_v31**（公式名决定日志文件名），编译通过。
2. 挂图：目标合约 **1 分钟**图（切片对拍用单合约图，如 P2505，`MapToMain=False`）。
3. 追加 **同合约日线** 图层（见第 3 节），两图层同步数据范围。
4. 图表「加载 K 线数量」调大：1 分钟数据量参考——单切片分段每次约 2.7~5 万根、整段 18~60 万根，建议 ≥16 万留余量。
5. 回测区间 = **预热起点 ~ 切片终点**；参数 `TradeStartDate` = **实际开仓日**（起点与开仓日分离，预热期不交易）。
   ⚠️ **硬性预热要求：`TradeStartDate`（首个目标信号日）之前，日线图层必须已积累 ≥61 根日线**
   （WinSize=61，N 计算要读到 `Data1.Close[61]`）——即图表数据范围起点须提前到 TradeStartDate 前
   **≥61 个交易日（约 3 个月）**。日线不足的后果：N 静默偏高/窗口退化产生假突破（切片 5 事故，
   详见第 9 节 FAQ）。切片参数表的「回测起点（预热）」列即按此规则排定。
6. 回测设置：初始资金 100 万；保证金率/手续费/滑点由公式 OnInit 设置（12% / 0.000023 按金额 / 1 跳），
   回测对话框保持默认即可。注：日志中 `SetMarginRate/SetCommissionRate/SetSlippage` 显示 **False 属正常现象**，
   设置仍然生效（切片终值与聚宽对拍一致可证）。
7. 跑完读回测报告 + 日志（见第 8 节）。

### 4.3 已实测对拍结果（v3.1 双图层）

- 切片 **4/5/6** 与聚宽逐笔对齐（方向/手数/时间 ±1 分钟），段末权益：切片 4 = 1,019,880（Δ−760，−0.07%）、
  切片 5 = 1,113,820（Δ−2,520，−0.23%）、切片 6 = 1,010,400（Δ+2,160，+0.21%）——与 v3.0 完全一致。
- v3.0/v3.1 同段 DAILY 日志逐日全等（2024-08-27 起抽查 N/EL/XL/ES/XS/equity 全部相同）。
- 探针 `PTrendTurtle_MultiSrc_Probe` 实测：N 对拍 43/43 全部命中 base1（日线源直读 ≡ v3.0 环聚合）。
- 判定标准建议：**方向、手数、时间（±1 分钟）必须一致**；价格允许 1~数跳差；非换月段平仓盈亏偏差 ≤2%；
  换月段允许更大偏差（TB 原生换仓 vs 聚宽两日确认手动平移，机制不同）。

### 4.4 与 v3.0 的操作差异

- **重跑无需关闭图表**：v3.1 全局状态随 OnInit 复位（v3.0 环数组清不掉，重跑必须关图重开）。
- 主连图（P9888，MapToMain=True）回测为**后复权价格口径**，成交价/手数与聚宽原始价不可直接比，
  仅用于策略自身的连续口径验证；与聚宽对拍请用单合约切片图。

## 5. 模拟怎么用

1. **挂图**：建议主连 P9888 **1 分钟** + 同合约日线图层，`MapToMain=True`（完整演练实盘换月链路）；
   或单合约图 + `MapToMain=False`（不演练换月）。
2. **数据范围**：1 分钟图加载数量默认即可（v3.1 不需要 1 分钟预热建环）；**日线图层加载数量 ≥100 根**
   （硬要求 ≥62 根日线）。
3. 运行模式 **K线收盘模型**；把图表/交易单元挂接**模拟期货账户**。
4. 启动后核对日志头部：`IsLiveTrade=True`、无 data1 错位 ERROR。启动时平台先**回放历史 bar**
   （历史回测机制，**不发单**），用于恢复 N/通道与台账；到达实时 bar 后才实际发单。
   若账户已有持仓而台账为空 → 首个持仓 bar 出现 `STATE_REBUILD` 自动按平台持仓重建。
5. `TradeStartDate` 若设在未来 → 首 bar 记 `TRADE_GATE` 警告、不产生任何交易动作（防呆；把参数改到过去即解除）。
6. **验证清单（建议挂 ≥1 个月再上实盘）**：
   - 每日 14:45 `DAILY` 快照的 N/四通道与行情软件手工计算一致；
   - 信号触发 → 模拟账户委托方向/手数/价格与日志一致；
   - 断线重挂 → 出现 `STATE_REBUILD` 且手数恢复正确；
   - 主力换月日（主连图模式）→ 出现 `ROLLOVER` 日志 + 台账重建。
7. 恢复语义须知：重启后 `UnitCount`（unit 数）按平台建仓次数恢复，极端情况与真实档位差 1；
   `S1Skip` 跳过标记不跨重启保存。

## 6. 实盘怎么用

挂载步骤与模拟完全相同，另注意：

1. **账户与下单**：挂接实盘账户；资金自动用 `A_CurrentEquity / A_FreeMargin`；
   下单吃盘口对手价（跨价差保成交），盘口无效（未连线/休市）退回理论触发价。
2. **换月（主连图 P9888 + MapToMain=True）**：委托自动映射真实主力合约；换月由平台原生
   自动换仓完成（等持仓量），公式检测 `MainSymbol()` 变化后重建台账基准并记 `ROLLOVER` 日志。
   注意：**回测下 MainSymbol() 恒为当前实盘主力**（如 p2701），ROLLOVER/重建仅在实盘生效——
   回测日志看不到换月行是正常的。
3. **单合约图（MapToMain=False）**：公式不做任何换月处理，到期前需自行平仓换月。
4. **风控注意**：
   - data1 图层数据异常（刷新失败 ERROR）→ 公式**拒绝一切交易**（含已持仓位的止损/出场/加仓；
     每根新 bar 自动重试，数据恢复即自愈）。发现 `N/四通道刷新失败` 日志请立即检查 data1 数据源。
   - 委托被拒（停板等）→ `OPEN_FAIL/CLOSE_FAIL` 日志，下一 bar 自动重试。
   - 海龟为趋势跟踪策略，切片属于"已知行情"的参数验证；实盘前务必先模拟 ≥1 个月，
     逐日核对日志与实际委托一致。
5. **日志文件**：实盘按物理日分文件（文件名带日期 `PTrendTurtle_v31_日志_yyyyMMdd.tbf`），
   同日续写不清空。⚠️ **同一台机器同日跑回测与实盘、且 LogDir 相同时**，回测 OnInit 会删除
   当日日志文件——回测与实盘请设置**不同的 LogDir**（或不同公式名）。

## 8. 日志关键行速查

| 关键字 | 含义 |
|---|---|
| `entry OPEN` / `add OPEN` | 开仓/加仓成功（dir/lots/price/N/stop/units/equity） |
| `stop CLOSE` / `exit_breakout CLOSE` | 2N 共享止损 / 反向突破出场平仓（含 pnl） |
| `OPEN_SKIP` | 手数不足跳过（保证金/上限约束；按日节流） |
| `OPEN_FAIL` / `CLOSE_FAIL` | 委托被拒（停板等），下一 bar 自动重试 |
| `S1_SKIP` / `BREAKOUT_SKIP` | 系统1 跳过规则触发 |
| `ROLLOVER` | 主力合约切换（仅实盘；随后可能伴随台账重建） |
| `STATE_REBUILD` | 台账按平台持仓重建（重启/不一致自愈） |
| `LEDGER_CLEAN` | 空仓残留台账清理 |
| `DAILY` | 每日 14:45 快照（N/EL/XL/ES/XS/units/stop/equity/d1） |
| `N/四通道刷新失败` | ERROR：data1 图层缺失/合约错位/历史不足/参数越界 → 拒绝交易，每根新 bar 自动重试（日志按交易日节流） |
| `TRADE_GATE` | 实盘未到 TradeStartDate，不会产生交易动作 |
| `=== 运行结束` | 末根 bar 期末对账（BarCnt/pos/contracts/lots/equity） |

## 9. 常见问题（FAQ）

- **Q：日志里 SetMarginRate 等返回 False，设置没生效？** A：生效。返回值显示语义未明，
  但切片终值与聚宽按 12%/0.000023/1跳 的对拍一致，证明设置已应用。
- **Q：回测日志里 MainSymbol 显示 p2701 之类"未来合约"？** A：平台行为——回测下 MainSymbol()
  恒为当前实盘主力，不影响回测；换月检测/重建仅实盘生效。
- **Q：出现 `N/四通道刷新失败`？** A：data1 图层没追加/合约与 data0 不一致/data1 历史不足 61 根/
  EntryN、ExitN 参数大于 61。修复后每根新 bar 重试即自动恢复（无需等次日）。
- **Q：回测 N 值偏高、手数偏少或出现假突破？** A：日线历史深度不足（见第 3 节第 4 条），
  把图表数据范围（两图层同步）提前到首个信号日前 ≥61 个交易日再跑。
- **Q：v3.1 和 v3.0 怎么选？** A：回测对拍两者等价；v3.1 重跑不用关图表、日线口径更贴近交易所官方日K，
  推荐新运行用 v3.1。若日线图层不便挂载（部分环境限制），v3.0 单图层方案仍可用。
- **Q：NPeriod/NSmooth 设成 0 或负数会怎样？** A：公式已内置 NaN 守卫——CalcDailyN 结果归 0、
  记 ERROR 并当日拒绝交易，不会用无效 N 开仓。
